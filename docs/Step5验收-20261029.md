## 2. 与设计稿预期不一致的地方（记录，不视为失败）

1. **DB 排他锁下 `/v1/recall` 没有返回空**——实测 24ms 正常返回。原因是 WAL 模式下排他写锁不阻塞读。
   设计稿写的「/recall 返回空」在 WAL 下不会发生；这比预期更好，不必改代码。
2. **SIM_GATE 的标定用片段复述做代理**，真实同义改写问句尚未覆盖。结论偏乐观：改写问句
   （如「你还记得上次说的那个拼团吗」实测 0.5498）仍可能贴在门槛下沿，当前靠「短查询补上下文」缓解，
   门槛维持 0.55 不变。

## 3. 本次修复

**embedder 阻塞写队列**（唯一违反「任何情况下都不能卡死」的问题）：

- 现象：`QQ_MEMORY_MODEL_DIR` 指向空目录 + 网络不可达时，首次写入卡住 **>25s** 未返回；
- 原因：`warmup()` 在锁内直接联网加载，异常处理要等网络超时；
- 修复（`a4c9c2c`）：缓存目录没有 `onnx` 且未开 `QQ_MEMORY_MODEL_DOWNLOAD` 时**立即降级、不发请求**；
  开了下载则后台线程加载（`state=loading`，写入先存空向量）；正常加载受
  `QQ_MEMORY_MODEL_LOAD_TIMEOUT`（默认 20s）约束；
- 复测：空目录 → `degraded=true`、写入 **42ms**；正常目录 → `ready`、写入 22ms、向量 2048 字节。
