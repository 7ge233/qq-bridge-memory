# SIM_GATE 标定记录（2026-10-29）

工具：`calibrate_gate.py`（只读，DB 以 `mode=ro` 打开）。

## 方法

- **相关样本**：从库里取 50 条 `is_active=1` 且有向量的记忆，各截 6~14 字正文片段
  （模拟用户复述时的短查询，如「加湿器拼团」），与**它自己**那条记忆算余弦。
- **不相关样本**：同一片段与随机 300 条其他记忆算余弦，共 11900 对。
- 统计门槛下的「相关召回率」与「不相关误召率」。

这只是**代理标定**：真实用户问句多为同义改写，难度高于片段复述，所以下面结论偏乐观。

## 结论

1. **0.55 可以保留**：片段式查询下相关召回 100%、误召 3.47%，落在两个分布之间的合理位置。
   0.60 更干净（误召 0.98%）但会牺牲一点同义改写的余量。
2. **真正的问题在改写查询**：之前实测「你还记得我上次说的那个拼团吗」与目标记忆余弦
   **0.5498**，贴着门槛下沿。片段标定覆盖不到这类问句，说明**靠单一硬门槛不够**：
   短查询已经用 `context` 补齐上下文（见 docs/工程细节.md），这条路径比调门槛更重要。
3. 若后续要放宽，**改 env 不用改代码**：`QQ_MEMORY_SIM_GATE=0.50`（召回 100%、误召 10.97%）。
   不建议低于 0.50：不相关 p95 就是 0.5353，再低等于放弃硬门槛。
4. 重跑方式：`python calibrate_gate.py --samples 100 --negatives 500`；库变大后结论可能变化，
   **建议每次记忆翻倍时重跑一次**。
