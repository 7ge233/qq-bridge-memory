# 工程细节

本文承接 README 里放不下的实现细节：模块职责、标定取舍、数据库约定、事件时效（v2.3）。
面向要改代码或排查数据问题的人；只想跑起来看 [README](../README.md) 与
[integration/INSTALL.md](../integration/INSTALL.md)。

## 1. 模块职责

| 模块 | 要点 |
| --- | --- |
| `app.py` | `/v1/*` 走 `X-Memory-Token`；`/v1/recall` 永远 200；lifespan 里建库、warmup、启动写队列 |
| `console.py` | token→HttpOnly cookie（HMAC，12h）、CSRF、登录锁定、审计；列举/停用/软删/撤销取代/导入/导出；事件状态、批量操作与回填/审计维护页 |
| `writer.py` | 必记/选记（群聊 3 分钟 ≤2、10 分钟 ≤5）/不记；`message_id` 幂等；24h 内余弦 ≥0.95 且长度差 <20% 视为近似重复；fact_key 同事务取代；写队列上限 1000、满了丢最旧 |
| `retrieval.py` | 门控用信息量（jieba + DF，N=近 5000 条）；权限过滤（私聊不进群、群聊可拿 public）；FTS top30 ∪ 近 200 条候选；`0.7*sim + 0.2*freshness + 0.1*importance`，时间词 ×1.2；SIM_GATE 硬门槛；Top6 / 800 字 / 单条 300 字 |
| `handoff.py` | 画像 + 最近 12~40 条原文 + 未完成事项 + 话题 + 偏好；单节预算 150/900/150/100/150，总 1500；裁剪 ②→③→①→④→⑤；降级：完整包 → 仅最近 20 条 → "未能保存" |
| `embedder.py` | 懒加载；recall 路径不触发加载（保 300ms）；写路径可加载；加载失败/维度不符 → degraded；向量 L2 归一化 float32 BLOB |
| `textproc.py` | CQ 码/占位符清洗；token/路径/手机/证件/银行卡脱敏为 `[已脱敏]`；`^(忽略|无视|你现在是|从现在开始)` 打 `suspicious`；visibility/category/importance/tags 规则 |
| `temporal.py` | v2.3 相对时间归一化（明天/下周X/周末…），以消息 `happened_at` 为基准 |

实测（本地 512 维、模型已缓存）：`recall` p50 ≈ 18ms、p95 ≈ 22ms（首条冷启动除外）。
`Retriever.warmup()` 预热 jieba + DF 快照，避免首条召回吃 500ms。

## 2. 标定与取舍（都是踩过坑之后定的）

- **SIM_GATE 0.55 偏紧**：实测「你还记得我上次说的那个拼团吗」与对应记忆余弦 **0.5498**，
  低于默认门槛。上线前必须按 8.3 用 50 条真实问答对重新标定（通常 0.50~0.55），
  不要把 0.55 当成品参数。
- **门控分词保留代词/单字实词**：否则「我胃疼」会被「有效词 <2」误杀，违反 8.1 验收。
- **群聊流水全量写**：`conversation_turns` 对群聊所有非噪声消息落库（满足「至少唤醒 ±3」，
  且让 handoff 有连续原文）；`memories` 才受选记时间锁限制。
- **suspicious 降权 0.5**，保留记录、只降权（4.1.4）。
- **敏感内容先脱敏再入库**（4.1.4 优先于 4.1 的「不记」）：原文不落库，日志只记长度 + 哈希前 8 位。
- **短查询补齐上下文**：查询词 <3 且信息量不足时，用最近 4 条对话（240 字）补进门控与检索，
  否则「大后天呢？」这类省略句永远不触发召回。
- **问句日期锚定**：查询里出现相对时间就解析成具体日期，召回按同日加权，并在每条后标注
  「比所问日期早/晚 N 天」，避免把 10-30 的计划讲成 10-31。

## 3. 数据库约定

- 所有时间 ISO8601 带 `+08:00`。
- `scope_key = qq:<account>:private:<uid>` / `qq:<account>:group:<gid>`，由服务端计算。
- `embedding` 为归一化 float32 BLOB；`embedding_model` 写模型名，换模型必须整体重嵌入。
- 每个线程用自己的 sqlite3 连接，统一走 `db_init.open_db()`。
- **连接级 pragma 陷阱**：`journal_mode=wal` 保留在库文件里，但 `synchronous` /
  `foreign_keys` / `busy_timeout` 是每条连接各自的设置。裸 `sqlite3.connect()` 实测为
  `FULL / 0 / 5000`；禁止绕过 `open_db()`。

## 4. 事件时效（v2.3，schema v2）

设计稿见 [事件时效设计.md](事件时效设计.md)。

- **schema v2**：`memories` / `memories_archive` 新增 `event_at`、`valid_until`、`event_status`，
  索引 `ix_mem_event`；`SCHEMA_VERSION=2`，迁移只加列加索引，旧数据三列 NULL。
- **写入**：仅 `user` + `category=event` + 非 `fact_key` 时解析相对时间；
  `temporal.py` 以消息 `happened_at` 为基准，不依赖入库时间；解析不了就不写，保持旧行为。
- **召回**：`cancelled` 永远排除；`valid_until` 已过的 `planned` 默认不注入
  （`meta.expired_skipped` 计数），传 `include_past=true` 才作为"已过去"返回；
  未来事件渲染为 `计划中`，事件半衰期默认 7 天。
- **渲染**：有事件时间时行格式为
  `[10-26 说 · 事件 10-27 · 计划中 · 私聊 · 她] 明天我要出去玩`。
- **开关**：`QQ_MEMORY_TEMPORAL=0` 回到 v2.2；`QQ_MEMORY_INCLUDE_PAST=1` 默认允许过去事件。

### 4.1 历史事件回填

v2.3 之前的历史记录 `event_at` 为 NULL，不会被时效过滤。CLI：

```powershell
.\.venv\Scripts\python.exe backfill_temporal.py          # 默认 dry-run，只报告
.\.venv\Scripts\python.exe backfill_temporal.py --apply   # 落库（默认先自动备份）
```

只处理 `role='user'` + `category='event'` + `event_at IS NULL`；模糊表达（过两天/改天/下次）
保持 NULL，不猜。控制台「维护 → 数据修复」（`/console/maintenance`）提供同一能力：
dry-run 扫描、候选/可解析/模糊跳过统计、`apply` 前自动备份、CSRF、审计、二次确认
（须输入 `BACKFILL`）。扫描不写库，应用才写。

### 4.2 事件更新（Phase 2）

- **取消**：「不去了/不出去了/没去成/取消了/计划有变」→ 把同 scope 最近的 planned 改为
  `cancelled`；本条不会写成新的"明天"计划。
- **提问不算计划**：「后天怎么样」「那大后天呢？」不生成事件；只有陈述/确认才写。
- **改期**：「改到/改期/推迟/延后/提前到」→ 重新解析日期并更新原事件；解析不出就只记录、不猜。
- **assistant 最终拍板**：「那就后天 / 选好了就周末 / 确定下周三」保留选中日期，
  取消同 scope、最近 30 分钟内其他 planned；问句不算拍板。
- **只读审计**：`python audit_event_plans.py` 或 `--json`，只报告
  "同 scope 多个 planned 日期 / 过期仍 planned"，不写库；维护页内嵌同一份审计。
- **状态字段**：`state`（active/inactive/deleted）是唯一真相，`is_active`/`deleted_at` 由 `store.set_state()` 派生同步；启动时 `resync_state()` 对齐。

**批量操作**：记忆页可勾选多条，一个下拉统一改状态——启用/恢复、停用、软删，以及事件进度（计划中/已完成/已取消，只对事件记忆生效）；须勾选确认框（勾了才解锁按钮），写审计。
- **handoff**：最近对话与未完成事项带 `（事件 YYYY-MM-DD）`；过期/取消事件不进 open_loops。
